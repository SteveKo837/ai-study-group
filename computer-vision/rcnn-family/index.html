Each model keeps more work inside the network and shares more computation. The story is: proposals become faster, features become shared, and masks need better alignment.

R-CNN: Original Architecture Figure

What changed?

R-CNN brought CNN features into object detection by classifying region proposals instead of sliding a classifier over the whole image.

  • Solved: stronger features than hand-designed detection pipelines
  • Bottleneck: about 2000 CNN forward passes per image
  • Still problematic: external proposals, crop/warp distortion, multi-stage training
Source: Girshick et al., “Rich feature hierarchies for accurate object detection and semantic segmentation,” arXiv:1311.2524, Fig. 1.

Selective Search

External Proposal Means “Outside the Neural Network”

Selective Search gives R-CNN and Fast R-CNN many candidate RoIs before the CNN makes class predictions.

  • It is class-agnostic: it proposes “object-like region,” not “dog.”
  • It keeps boxes from many merge levels.
  • It usually returns many proposals so recall is high.
RoI = candidate box that might contain an object
Dog proposal visualization generated locally from SLIC superpixels plus proposal-style grouping.
Selective Search Details

How Region Merging Actually Works

1. Superpixels
small coherent regions
2. Adjacency Graph
neighbor regions connected
3. Similarity
score every neighbor pair
4. Greedy Merge
merge highest score pair
5. Update
features + neighbors
6. Store Boxes
many merge levels
similarity = color + texture + size + fill

Color: do regions have similar color histograms?

Texture: do local patterns look similar?

Size: prefer merging small regions early.

Fill: does the combined box tightly fit both regions?

Different color spaces and merge strategies are used to increase proposal diversity.

Selective Search is greedy hierarchical grouping, not a learned detector.
Animated Example

Selective Search Merge Sequence on the Dog Image

neighbor regions → merged region → proposal box
  1. Neighbor regions are connected in the adjacency graph.
  2. The highest similarity pair is merged first.
  3. Region features are recomputed for the merged region.
  4. A bounding rectangle is stored as a proposal box.
  5. The process repeats, producing small, medium, and large RoIs.

Selective Search saves boxes throughout the merge tree, so it can propose dog parts, one dog, or a group of dogs.

Animation loops through 2-3 merge levels: neighbors, merged region, proposal box.

Fast R-CNN: Original Architecture Figure

What changed?

Fast R-CNN computes convolutional features once for the entire image, then extracts proposal features from the shared feature map.

  • Solved: repeated CNN work from R-CNN
  • Still uses: external Selective Search proposals
  • Still problematic: RoI Pooling quantizes coordinates; proposals are not learned
Source: Girshick, “Fast R-CNN,” arXiv:1504.08083, Fig. 1.
Fast R-CNN Mechanics

RoI Pooling Happens on the CNN Feature Map

Image RoI: (80,48,240,208)

The proposal begins in original image coordinates. After the backbone CNN, coordinates are scaled down by the feature stride.

Example:

image RoI = (80, 48, 240, 208)

stride = 16

feature-map RoI = (5, 3, 15, 13)

The CNN feature map is a compressed version of the image. RoI Pooling chooses the matching rectangle on that compressed map.

Coordinate rule: divide image coordinates by backbone stride, then pool on feature-map cells.
RoI Pooling

Variable RoI In, Fixed Tensor Out

Every proposal can have a different shape, but the fully connected detection head needs a fixed-size tensor.

  • Map proposal to the shared feature map.
  • Divide the feature-map RoI into fixed bins.
  • Max-pool inside each bin.
  • Output shape is usually 7 x 7 x C.

RoI Pooling asks: inside this region, what is the strongest activation in each bin?

Real Fast R-CNN commonly uses 7x7 bins; 2x2 is shown for teaching.

Output for N proposals: N x 7 x 7 x C, regardless of original proposal size.
Numeric Example

RoI Pooling: 2x2 Max Pooling Toy Example

The selected RoI covers a 3x3 feature-map region. We divide it into 2x2 bins and take the max activation per bin.

  • Top-left bin max: 9
  • Top-right bin max: 8
  • Bottom-left bin max: 8
  • Bottom-right bin max: 9

The output remembers the strongest evidence in each spatial bin, while forcing every RoI into the same shape.

Real models usually use 7x7; this 2x2 example makes max pooling visible.
Quantization

RoI Pooling Rounds Coordinates

RoI Pooling quantizes both the RoI boundaries and the bin boundaries to integer feature-map cells.

  • For detection boxes, a little snapping is often acceptable.
  • For segmentation masks, one or two cells can shift object boundaries.
  • This is why Mask R-CNN replaces RoI Pooling with RoIAlign.

Rounding is tiny numerically, but masks are pixel-level outputs, so tiny spatial errors become visible.

Key phrase: quantization error creates spatial misalignment.
RoIAlign

RoIAlign Keeps Floating-Point Geometry

RoIAlign does not snap the RoI to integer cells. It samples points inside each bin and computes values with bilinear interpolation.

  • RoI boundary stays floating-point.
  • Sampling points appear inside bins.
  • Each sample reads from nearby feature cells using interpolation.
  • Samples are aggregated into the output cell.

RoIAlign asks for the feature value at an exact location, even if that location lands between grid cells.

Mask R-CNN uses RoIAlign because masks require precise spatial alignment.
Numeric Example

Bilinear Interpolation at One Sample Point

If a sample point falls between four feature cells, RoIAlign blends their values according to distance.

Weighted sum:

10 × 0.0625 + 14 × 0.1875 + 18 × 0.1875 + 22 × 0.5625 = 19.0

  • Multiple sample points can be used inside a bin.
  • The bin output aggregates them, commonly by average or max depending on implementation.
Bilinear interpolation is the core difference from snapping/rounding.

Faster R-CNN: Full Architecture Diagram

What changed?

Faster R-CNN replaces external Selective Search with a Region Proposal Network that shares the same CNN feature map.

  • Solved: slow external proposal generation
  • Introduced: anchors, objectness, box regression, NMS
  • Still problematic: two-stage detection; many anchors must be trained and filtered
Diagram: Salih et al., UHDJST Fig. 3; Faster R-CNN method: Ren et al., arXiv:1506.01497.
Region Proposal Network

The RPN Slides Over the Shared Feature Map

one feature-map location

At every feature-map location, the RPN predicts proposals using a small sliding network.

  • A 3x3 conv sees local context around that location.
  • For each anchor, it predicts objectness: object vs background.
  • For each anchor, it predicts box offsets: (tx, ty, tw, th).
  • Top proposals are kept after Non-Max Suppression.
per location outputs = A objectness scores + A box regressions
RPN proposals are learned from the feature map, not generated by Selective Search.
Anchor Boxes

Anchors Are Default Guesses at Each Location

An anchor is a reference box. It is not the final detection.

  • Example: 3 scales x 3 aspect ratios = 9 anchors per feature location.
  • The RPN scores each anchor as object or background.
  • The RPN regresses each anchor into a better proposal box.

Anchor boxes are default guesses. The RPN learns which guesses are object-like and how to adjust them.

Animation: anchors appear at one location, then a good anchor is regressed into a proposal.
Anchor Training

How Anchors Become Positive, Negative, or Ignored

During training, anchors are matched to ground-truth boxes by IoU.

  • Positive: high IoU with a ground-truth object, or best anchor for that object.
  • Negative: low IoU with all objects.
  • Ignored: middle range; not used for classification loss.

Typical Faster R-CNN-style thresholds: positive >= 0.7, negative <= 0.3. Exact values vary by implementation.

IoU matching teaches objectness and which anchors should regress toward each dog.
NMS

Non-Max Suppression Removes Duplicate Proposals

The RPN may produce many overlapping boxes around the same dog. NMS keeps the highest-scoring box and removes highly overlapping duplicates.

  1. Sort proposals by objectness score.
  2. Keep the best proposal.
  3. Remove boxes whose IoU with it is too high.
  4. Repeat for the remaining boxes.
NMS reduces many RPN boxes to a manageable set of RoIs for the detection head.

Mask R-CNN: Original Architecture Figure

What changed?

Mask R-CNN extends Faster R-CNN with a parallel mask branch and replaces RoI Pooling with RoIAlign.

  • Solved: instance-level segmentation, not only boxes
  • Important fix: RoIAlign avoids quantization misalignment
  • Still problematic: two-stage model; mask resolution is predicted per RoI then resized
Source: He et al., “Mask R-CNN,” arXiv:1703.06870, Fig. 1.
Mask R-CNN Mechanics

Mask R-CNN Adds a Spatial Mask Head

box + mask for one dog instance

For each RoI, Mask R-CNN predicts three outputs.

  • Class head: what category is this RoI?
  • Box head: refine the bounding box.
  • Mask head: predict a small per-class binary mask, often 28 x 28.

Final Takeaways

What Students Should Remember

  • R-CNN is slow because it runs CNN on each proposal crop.
  • Selective Search greedily merges superpixels and stores many class-agnostic boxes.
  • Fast R-CNN shares the backbone feature map and uses RoI Pooling.
  • RoI Pooling creates fixed-size features but rounds geometry.
  • Faster R-CNN learns proposals with an RPN and anchor boxes.
  • Mask R-CNN uses RoIAlign and adds a mask branch.

Detection answers “where is the dog?”

Instance segmentation answers “which exact pixels are that dog?”

End with the idea: proposals → shared features → learned anchors → aligned masks.
