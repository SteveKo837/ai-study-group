資料平行的四個問題（本堂重點）

① 模型沒有變小

每張卡仍要放整份模型 → 「一張卡裝不下」的模型，DP 根本救不了。

② 通訊隨規模長大

梯度 all-reduce 每步要搬 ≈ 2× 參數量；模型越大、卡越多，同步成本越兇。

③ 記憶體重複浪費

權重、梯度、optimizer 狀態每張卡各存一份 → ZeRO/FSDP 把它們切開，但換來更多通訊。

④ 推論延遲無解

decode 是 memory-bound；DP 只增吞吐、對單一請求的延遲沒幫助，KV cache 還各卡獨立。

①最致命：DP 切資料、不切模型。要裝下大模型、又想壓通訊，就得把「模型本身」拆開。

切模型本身：張量 / 管線 / 專家平行

既然 DP 不切模型，就換三種「切模型」的平行——各自切不同的軸，付不同的通訊代價。

Tensor Parallel

TP · 張量平行

切什麼

切「層內」：一個矩陣乘橫著切到多卡

每層 2 次 all-reduce

通訊最重 → 必須待在 NVLink 域

Pipeline Parallel

PP · 管線平行

切什麼

切「層間」：不同層放不同卡，像流水線

點對點傳 activation（p2p）

有 bubble（頭尾閒置）

Expert Parallel

EP · 專家平行

切什麼

切「MoE 專家」：不同 expert 放不同卡

all-to-all 路由 token

省 FLOPs、不省通訊

實務是「3D/4D 混合」：DP + TP + PP(+ EP) 疊用。切得越細、卡間通訊越密——通訊就成了新瓶頸。

通訊變瓶頸：頻寬階梯決定誰住哪

卡間搬資料的速度差一個數量級往下掉。哪種平行「通訊多」，就得住在「線快」的那一層。

晶片內 HBM

~3.35 TB/s

（單卡基準）

NVLink 5 / NVSwitch

~1.8 TB/s 雙向

scale-up：TP、EP 住這裡

跨節點 InfiniBand / Spectrum-X

~50–100 GB/s / GPU

scale-out：DP、PP 可容忍

PCIe Gen5

~64 GB/s

沒 NVLink 時的卡間路（會被拖死）

心法：把「通訊最兇」的平行（TP/EP）綁在最快的線（NVLink）；「通訊稀」的（DP/PP）才放去跨節點。

NVIDIA 解法① scale-up：把多顆綁成一顆大 GPU

NVLink + NVSwitch 用「記憶體語意」把整個機架的 GPU 連成一個高頻寬域——TP/EP 的家。

NVLink 5

1.8 TB/s（雙向）

18 條 × 100 GB/s；≈ PCIe Gen5 的 14×

NVSwitch（4 代）

全連通 fabric

72 顆非阻塞互連；可擴到 576 GPU / 1 PB/s

GB200 NVL72

72 顆 = 一個域

130 TB/s 聚合頻寬，當一顆「大 GPU」用

2026 最新 · Rubin

NVLink 6：3.6 TB/s / GPU（NVLink 5 的 2×）

Vera Rubin NVL72：260 TB/s 聚合

CES 2026 發表、H2 2026 出貨；Rubin CPX 把 prefill 拆出來做（PD 分離，第四堂）

scale-up 的意義：一個 NVLink 域內，72 顆 GPU 的 HBM 像一大池——大模型的 TP/EP 就攤在這池裡跑。

NVIDIA 解法③ scale-out：跨節點的網路

一個機架塞不下時，用網路把多台節點串成 AI factory——這裡走「訊息語意」（RDMA）。

InfiniBand（Quantum）

NDR 400 / XDR 800 Gb/s

HPC 老本行，原生支援 SHARP

Spectrum-X 乙太

為 AI 調過的以太網

adaptive routing + 壅塞控制，跑 RoCEv2

GPUDirect RDMA

遠端 NIC 直達 HBM

繞過 CPU，跨節點也能直接讀寫對方 GPU

scale-up vs scale-out

scale-up（NVLink）

記憶體語意、~TB/s、機架內 → 綁 TP/EP

scale-out（IB/乙太）

訊息語意、~百 Gb/s、跨節點 → 綁 DP/PP

兩層網路差一個數量級：所以「通訊密的平行留機架內、稀的才跨節點」不是選擇，是被頻寬逼的。

組起來：一個大模型怎麼跑在 NVL72 上

把前面的技術疊起來，看一個「一張卡裝不下」的模型實際怎麼被攤開。

① 一個 NVLink 域 = 一顆大 GPU

GB200 NVL72 把 72 顆連成 130 TB/s 的域 → 大模型的權重攤在這一池 HBM 裡放得下。

② 域內做 TP + EP

層內矩陣切到多卡、MoE 專家散到多卡，每層的 all-reduce / all-to-all 跑在 NVLink，並用 SHARP 加速。

③ 跨域做 DP + PP

多個 NVL72 之間用 InfiniBand / Spectrum-X 做資料平行的梯度同步、管線的 activation 傳遞。

④ NCCL 統籌

上層一律用 NCCL 呼叫集合通訊，自動選 NVLink 還是網路、要不要走 SHARP。

真實訓練＝DP × TP × PP × EP 的混合，每一軸配一種通訊、一條線——互連技術就是讓這套疊得起來。
