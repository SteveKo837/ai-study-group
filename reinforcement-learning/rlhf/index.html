SFT 的能力邊界
SFT 會提高 demonstrations 的 likelihood；它無法直接利用「回答 A 比回答 B 好」的相對偏好訊號，也不會自動解決資料分布外的行為。
2-2 · Reward model

把「哪個回答比較好」學成一個 scalar。

同一個 prompt 下收集 preferred 與 rejected responses，RM 以共享權重分別打分，再用 pairwise ranking loss 學習人類偏好。

Chosen yᵥ

「以清楚步驟解釋，答案正確且符合指令。」

rφ(x, yᵥ) = 2.7
Rejected yₗ

「語氣流暢，但忽略限制並包含錯誤結論。」

rφ(x, yₗ) = 0.8
Bradley–Terry preference model
P(yᵥ ≻ yₗ | x) = σ(rφ(x,yᵥ) − rφ(x,yₗ))
LRM = −log σ(rφ(x,yᵥ) − rφ(x,yₗ))

N+ 值得帶走的 implementation details

Input semantics

RM 與 value head 都看完整的 query + response。

Scalar extraction

從 EOS 或最後有效 token 取 reward；必須與 padding 語意一致。

Head initialization

Reward head 約以 N(0, 1/√(d_model+1)) 初始化。

Output normalization

用 SFT demonstrations 將初始 RM output 校正至約 mean 0、variance 1。

Training budget

N+ 的 SFT 與 RM 各訓練一個 epoch，降低 overfitting 風險。

Evaluation

Accuracy、calibration、judge agreement 與最終 policy quality 分開報告。

兩種 normalization
RM output normalization 發生在 reward model 建立階段；reward whitening 發生在 PPO rollout／batch 處理。兩者目的與統計量不同。
InstructGPT · Prompt-grouped comparisons

同一個 prompt 的所有比較，一起計算 loss

InstructGPT 讓標註者對同一 prompt 的 K = 4～9 個 completions 排序，產生 K(K−1)/2 組 pairwise comparisons。 訓練時將整組比較作為一個 batch element；一個 minibatch 可以包含多個 prompt groups。

Worked example · K = 3

用三個回答簡化示範：同一 prompt x，人工排序 A > B > C。

Completion A

rA = rφ(x,A)

Completion B

rB = rφ(x,B)

Completion C

rC = rφ(x,C)

每個 completion 各算一次 RM score，重用於 (A,B)、(A,C)、(B,C) 三組比較。

One prompt · Mean pairwise loss
Lx = −⅓ [log σ(rA − rB)
+ log σ(rA − rC) + log σ(rB − rC)]

再對 minibatch 中各 prompt 的 Lx 取平均，一起反向傳播。Loss 仍是 pairwise ranking loss。

WHY

降低過度擬合

同一 prompt 的 comparisons 高度相關。若拆成獨立資料點再 shuffle，每個 completion 可能參與 K−1 次不同的 gradient updates；作者觀察到即使只有一個 epoch 也會 overfit。
HOW

重用 forward 計算

先取得 K 個 completion scores，再組合出全部 K(K−1)/2 個 loss terms；同一 completion 不必因不同 pair 反覆 forward。
一次聚合更新，保留全部 pairwise 訊號
每個 completion 仍會參與 K−1 個 loss terms，但這些梯度會在同一次更新前聚合。作者報告 validation accuracy 與 log loss 改善；這是該實驗的結果，並非普遍不會 overfit 的保證。

來源：InstructGPT，§3.5 Reward modeling、式（1）與註腳 5（第 8 頁）。 此處的分組訓練細節來自 InstructGPT。

2-3 · PPO for language models

四個模型、一條 response、兩種 KL 語意。

Actor 產生 token；RM 評估完整回答；critic 預測 partial response 的未來 return；reference policy 限制 actor 偏離 SFT。

Model topology

Actor更新

Policy πθ

由 SFT 初始化，生成 response，接受 PPO policy gradient。

Anchor凍結

Reference πref

SFT model 的 frozen copy；計算每個 token 的 KL penalty。

Judge凍結

Reward model rφ

以 pairwise preferences 訓練；對完整 response 產生 sequence reward。

Critic更新

Value Vψ

可從 RM 或 policy backbone 初始化；預測每個 prefix 的未來 regularized return。

Reference policy ≠ old policy
Reference policy 是固定的 SFT anchor，服務 KL regularization；old policy 是產生當前 rollout 的 snapshot，服務 PPO importance ratio 與 clipping。

rθ(x,y)

Frozen Reward Model 對完整 prompt + response 給分，鼓勵 policy 產生人類偏好的回答。
2 · KL CONTROL

−β log(πRL / πSFT)

+γ E[log πRL(x)]

這個 objective 和 PPO clipped loss 的關係
上式描述想最大化的整體訓練目標。實作時，前兩項形成 RL rollout 的 regularized reward，再用下方的 Advantage 與 PPO clipped surrogate 更新 policy；第三項則是平行加入的 language-model auxiliary objective。原式的 policy 參數記為 φ、RM 參數記為 θ，和本頁其他段落採用的 θ／φ 剛好相反。

原式中的 γ 是 pretraining loss coefficient，並非下方 GAE 使用的 discount factor γ；為避免混淆，本頁後面的等價寫法改記為 αptx。InstructGPT，式（2）

PPO-ptx 是一條平行的資料路徑
Pretraining data 不參與 response rollout、RM scoring、KL reward 或 GAE。它以標準 next-token log-likelihood 形成 auxiliary gradient，與 PPO gradient 一起更新 policy，目的是降低 RLHF 對既有語言能力造成的 regression。上式用 αptx 區分這個係數與 GAE 的 discount γ；InstructGPT 原文式（2）將 pretraining loss coefficient 記為 γ。純 PPO 將此係數設為 0。

03 · Direct preference optimization

把 RM 與 policy optimization 合併成一個分類 loss。

標準 DPO 直接使用固定 preference pairs，不建立顯式 RM、不做 online rollout，也不需要 value model。

DPO objective
LDPO = −log σ( β [ log πθ(yᵥ|x)/πref(yᵥ|x)
− log πθ(yₗ|x)/πref(yₗ|x) ] )
Implicit reward
rθ(x,y) = β log [πθ(y|x) / πref(y|x)] + C(x)

C(x) 只依賴 prompt，在 chosen／rejected 的 reward difference 中消去。β 控制 policy 相對 reference 的偏移尺度。

Training loop
1固定 preference dataset
2Policy + frozen reference forward pass
3計算 chosen / rejected log-ratio
4Binary classification update
適合 LLM，也不是數學上限定 LLM
DPO 依賴可計算的 policy／trajectory likelihood 與 pairwise preference model。它在語言模型上特別自然，也能延伸到其他具備這些條件的 policy。
Offline 的限制
訓練只看既有 preference pairs；品質受資料分布、chosen／rejected 長度偏差、reference checkpoint 與 β 影響。

05 · Reward granularity

偏好、結果與過程，是兩個分類軸。

經典 preference RM 判斷人類偏好；數學 ORM 判斷最終 correctness；PRM 則把 supervision 切到每個 reasoning step。

Preferenceresponse scalar

Pairwise RM

資料是 chosen／rejected response；目標是預測相對偏好，常作為通用 RLHF 的 terminal reward。

Outcomesolution scalar

ORM

只監督最終答案或整條 solution。成本較低，數學與程式任務可使用 automatic verifier。

Processstep rewards

PRM

對每個推理步驟標註 correctness。credit assignment 更細，但標註、步驟切分與 rubric 成本更高。

《Let’s Verify Step by Step》的證據邊界
論文直接驗證的是固定 generator 下的 best-of-N selection：PRM 在特定 MATH 設定優於 ORM。它沒有直接證明使用 PRM 做 RL 後會得到同幅度提升。
正確 outcome 不保證正確過程
ORM 可能接受錯誤推理後碰巧命中答案；PRM 改善可診斷性，但可讀的 chain-of-thought 也不必然忠實反映模型內部計算。
